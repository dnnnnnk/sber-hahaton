# Аудит перед код-фризом

Дата: 17 октября 2026. Итоговая приёмка поверх `main` @ `4a28d01`, включая P2.

Основание — четыре пункта P0 из `prompt-codex-polish.md`. Вместо проверки только переходов в телефонной
рамке выполняется полный прогон Chromium **и WebKit при viewport 375×812**, DPR 2, с touch.
Проверяются все восемь экранов с прокруткой, зоны/якоря, все включённые эффекты и их варианты, CMS,
альбом и debug. Скриншоты просматриваются визуально; автоматические проверки контролируют действия,
геометрию, ресурсы, завершение эффектов, консоль, HTTP и внешние запросы.

Методика и воспроизведение: [docs/P0_QA.md](docs/P0_QA.md). Дополнительные проверки P2:
[docs/P2_QA.md](docs/P2_QA.md). Физические телефоны проверяются отдельно по `docs/DEVICE_QA.md`.

## P0 — обязательно до защиты

- [x] **Итоговый аудит всего продукта.** Полный прогон Chromium и WebKit при 375×812 после исправлений
  пройден; 40 проверок и 22 варианта эффектов в каждом браузере. Консоль, HTTP, предупреждения и внешние
  запросы — 0. Протокол и просмотренные контактные листы: [docs/qa/p0/](docs/qa/p0/README.md).
- [x] **Чужие образы на экранах.** Аватар на `tasks`, банки на `transfer` и карточки на `moneybox` перекрыты
  нейтральными локальными плашками; нижняя товарная подборка заменена собственными идеями. `content` всегда
  рендерится собственной HTML-композицией. Плашки имеют `pointer-events: none` и не меняют касания зон.
- [x] **Зоны и якоря после визуальных правок.** Рамки `avatar`, `card`, `balance`, `tabbar`, дел, копилок,
  `success`, `goal`, `trophy` и кнопок сверяются в обоих браузерах. Голограмма совпадает с картой при прокрутке;
  плашки не участвуют в hit-testing. Действия проверяются настоящими касаниями, видимые кнопки — сеткой
  3×3 точек. Проценты находятся в `app/screens.js`.
- [x] **Вес экранов.** Все 9 WebP шириной 750 px; суммарно 920 160 байт при цели ≤ 1,5 МБ. Первый экран
  загружается сразу, остальные последовательно после первой отрисовки. Дополнительное сжатие не требуется.
- [x] **Альбом обходил красную зону.** Debug/API мог открыть альбом поверх перевода → запрет перенесён в
  `openAlbum()`. Ошибка воспроизведена до исправления в Chromium и WebKit; добавлена регрессия.
- [x] **Отложенный/играющий звук переживал stop/mute.** WAV мог запуститься после загрузки уже на переводе,
  а глобальный mute останавливал только синтез → единая отмена всех голосов, включая незавершённые fetch/decode,
  остановка при красной зоне и фоне. Вибрация отменяется вместе с эффектами.
- [x] **QR в исходном растре.** На главном оставался QR вопреки ограничениям → собственная нейтральная
  плашка со звездой, без изменения зон и без нового ассета. Кот на карте сохранён по исходному плану.
- [x] **CMS могла задать внешний адрес ассета.** Строка `sound`/`src` принималась без проверки адреса →
  разрешены только локальные пути внутри `content/`, в том числе при фактическом разрешении URL.

## P1 — качество и демонстрация

- [ ] **Четыре заготовки остаются выключенными.** `flip-phone`, `balance-pretty-number`, `still-sleep`,
  `moneybox-milestones` имеют `enabled: false`. → Довести и включить по п. 11 исходного плана; не считать
  работающими эффектами при демонстрации P0. Текущая приёмка покрывает все 15 включённых записей.
- [ ] **Данные растровых экранов демонстрационные.** Экран пополнения показывает статичную оплату магазина,
  итог дел — три другие задачи; сумма баланса в растре не меняется вслед за debug, у мечты остался товарный
  комментарий. → Заменить эти фрагменты HTML-данными оболочки перед приёмкой полного сценария P1.
- [ ] **Часть элементов макета не подключена к действиям.** Создание копилки, финансовые действия мечты,
  отправка родителю, фильтр сложности и карточки контента остаются частью макета. → Подключить события
  оболочки или явно определить границы демо; основной маршрут приколов и все существующие зоны проверены.
- [ ] **Сальто у верхнего края.** Во время верхней фазы аватар частично выходит за границу телефона
  (`effects` на контактных листах). → При полировке P1 направить прыжок внутрь доступной области;
  это не меняет точность исходного якоря и не мешает касаниям.
- [x] **Чип разрешения не перекрывает контент.** Компактная доступная кнопка ✨ занимает неактивную центральную
  вкладку «Ассистент»; на экранах без таббара и в красной зоне скрывается.
- [x] **Текстовые артефакты макета.** Заголовки, пояснения и кнопки с подчёркиваниями закрыты собственными
  HTML-слоями; растровая первая строка дела заменена HTML.
- [x] **Все дела единообразны.** Пять строк рисуются одним HTML-компонентом с одинаковой геометрией, наградой,
  состоянием выполнения и запасом прокрутки под закреплённый таббар.
- [x] **Есть летний сценарий.** В июне–августе shake запускает собственные «Солнечные зайчики» с двумя вариантами.
- [x] **Варианты дел разнообразны.** У каждого из пяти дел по два безопасных визуальных варианта без наград.
- [x] **Глубокая валидация CMS.** Проверяются смысловые диапазоны настроек, расписаний, триггеров и эффектов.
  `maxParticles: 0` теперь действительно создаёт ноль визуальных частиц; диапазон настройки — `0..500`.
- [ ] **Доступность оболочки.** Добавлены русские названия, описания экранов, `aria-current`, `aria-pressed`,
  доступный диалог альбома и проверено дерево доступности браузера. Физический VoiceOver/TalkBack остаётся в
  сценарии `docs/DEVICE_QA.md`.
- [ ] **Реальные устройства.** Десктопные эмуляторы подтверждают логику, но не ощущения датчиков, звук, вибрацию
  и FPS. → Пройти `docs/DEVICE_QA.md` на iPhone Safari и слабом Android Chrome и записать результат в таблицу.

## P2 — реализация

- [x] **Звенящие копилки (п. 16).** Тряска в копилках запускает монетки в небольших кармашках карточек.
  Количество пропорционально прогрессу, есть гравитация, столкновения, мягкий синтезированный звон и вибрация.
  Суммы, цели и состояние накоплений эффект не читает и не меняет. Клиппинг не даёт монетам залезать на таббар.
- [x] **Жилец экрана (п. 17).** Собственная Капля появляется по двум тапам на карте на 9 секунд: катится от
  наклона, смеётся от тапа, удивляется от тряски, уходит по свайпу. Все pointer-слушатели пассивны;
  появление без звука, mute и уменьшение движения учитываются, подписки снимаются при завершении.
- [x] **Переходы и нажатия (п. 18).** Появление нового экрана за 220 мс, направление смены вкладок,
  мягкий отклик HTML-кнопок и растровых зон. Старые экраны не клонируются, ввод не задерживается;
  красная зона открывается без анимации, reduced motion отключает перемещение.
- [x] **Правила и CMS.** Оба прикола — обычные записи конфига с валидацией, подсказками в альбоме и кнопками
  debug. Уход на неподходящий экран завершает эффект. CMS очищает старую очередь и снимает активные подписки.
- [x] **Общий бюджет.** Капля, монетки и существующие частицы делят `maxParticles`, включая резерв до первого
  кадра. Проверены нулевой лимит и одновременный локальный/полноэкранный эффект при лимите 1.
- [x] **Красная зона.** Эффекты гасятся до ожидания картинки перевода; тост и альбом также скрываются немедленно.
- [x] **CMS без переполнения.** Скрытые radio выбора сезона наследовали ширину 100% и растягивали страницу,
  уводя фиксированную кнопку сохранения ниже видимой области. Поля ограничены своим label, проверяется
  сохранение при ширине 1280 и 375 px.
- [x] **Документация.** Обновлены контракт якорей, форматы эффектов, правила движка, оценка переноса в натив,
  сценарий показа за минуту и ручная проверка устройств.

## P2 — проверка и инфраструктура

- [x] Автоматический smoke/e2e-прогон Chromium и WebKit при 375×812: настоящие клики, пассивные жесты,
  прокрутка, точное число монет при 25%/100%, уход с экрана, красная зона, CMS, нулевой/общий бюджет,
  reduced motion, mute, модель visibilitychange и остановка общего цикла после обоих эффектов.
- [x] Визуальная проверка скриншотов Капли, монет и красной зоны; ошибки консоли, HTTP и внешние запросы

- [x] Замер P2 при CPU throttling ×4 в Chromium: полные карточки копилок (56 зарегистрированных монет)
  и Капля одновременно со снегом — по 60 FPS, p95 кадра 17 мс. Это настольная эмуляция нагрузки;
  реальные Android-устройства проверяются отдельно. Подробности — `docs/P2_QA.md`.
- [ ] CI для автоматического запуска smoke-тестов. Локальный запуск уже описан в README.
- [ ] Замер на физическом слабом Android и проверка датчиков/звука/вибрации на iPhone; сценарий расширен в
  `docs/DEVICE_QA.md`. Эмуляция не выдаётся за проверку реального телефона.

## Ручной smoke-check P0

1. Главный: карта и баланс совпадают с якорями; тряска и наклон запускают эффекты.
2. Дела: каждая строка нажимается; эффект рождается из своей строки; общий праздник имеет больший приоритет.
3. Копилки: все шесть карточек нажимаются; Lottie центрирована по `success`; `goal` совпадает с роботом.
4. Перевод: красная зона показана в debug, активный эффект прекращается, новый не запускается.
5. Контент и таббар: нет чужих образов, стыков активной вкладки и перехвата касаний плашками.
6. Альбом, CMS и debug открываются; консоль не содержит ошибок и внешних запросов.

P0 закрыт по четырём пунктам исходного плана. Открытые пункты P1 перечислены отдельно и остаются открытыми.

# Приёмка P0

17 октября 2026. Основание: четыре пункта P0 из `prompt-codex-polish.md`.
Проверяется текущая локальная версия поверх `main` @ `4a28d01`, включая P2.

**Результат: P0 пройден в обоих браузерах.** В каждом — 40 проверок и 22 естественно завершившихся
варианта эффектов; ошибок JS/HTTP, предупреждений и внешних запросов — 0.
Протокол, версии браузеров, SHA-256 исходников и скриншоты: [доказательства приёмки](qa/p0/README.md).
Регрессия P2 после исправлений P0 также пройдена в обоих браузерах:
[p2-regression.json](qa/p0/p2-regression.json).

подсветка якорей. Скриншоты оцениваются визуально, автоматические проверки дополняют этот просмотр.

## Найдено и исправлено

1. **Альбом в красной зоне.** Прямой вызов `openAlbum()` из debug обходил запрет жеста → запрет находится
   в самой публичной операции; регрессия воспроизведена в обоих браузерах до исправления.
2. **Файловый звук после ухода/выключения.** `fetch/decode` мог закончиться уже после mute или перехода
   на перевод, а играющий WAV не учитывался в общем mute → отмена регистрируется до загрузки;
   общий stop, mute, отключение и уход в фон отменяют звук. При красной зоне отменяется и вибрация.
3. **Растровый QR на главном.** Исходный QR оставался видимым вопреки ограничениям → нейтральная локальная
   плашка со звездой; без изменения существующих зон и без нового изображения.
4. **Внешний ассет из CMS.** Проверялся тип строки, но не адрес → валидация пути и повторная проверка
   при разрешении URL запрещают выход из `content/` и внешние запросы через конфиг.

`tests/sound.lifecycle.mjs`: шесть регрессий звука (отложенный mute/stop/disable/hidden и играющий
stop/mute) и отмена вибрации. Они используют управляемую модель WebAudio; браузерный прогон отдельно
проверяет переход в красную зону во время задержанной загрузки настоящего WAV.

## Ассеты

`tests/p0.assets.mjs` читает WebP-заголовки и считает файлы: **9 WebP, каждый шириной 750 px,
920 160 байт суммарно** (0,92 МБ при лимите 1,5 МБ). `content/`: **160 292 байта** при лимите 6 МБ.
Первый экран и таббар загружаются сразу; после его отрисовки остальные изображения последовательно
подгружаются фоном (`app/main.js`, `preloadImages`). Повторное сжатие не применялось.

## Воспроизведение

1. Из корня проекта запустить `python3 -m http.server 8000`.
2. С Node.js и установленным инструментом разработки Playwright выполнить:

```sh
node tests/p0.assets.mjs
node tests/sound.lifecycle.mjs
node tests/p0.audit.mjs
node tests/p2.smoke.mjs
```

Пути к установленному Playwright/браузерам задаются через `PLAYWRIGHT_MODULE` и
`PLAYWRIGHT_BROWSERS_PATH`; сервер — через `APP_URL`, результат — через `QA_DIR`.
Для одного браузера доступен `ONLY_BROWSER=chromium` или `ONLY_BROWSER=webkit`.
Для дополнительной съёмки эффектов в середине анимации: `VISUAL_ONLY=1 ONLY_CHECK='effect ' node tests/p0.audit.mjs`.
Этот режим делает снимки и останавливает эффекты; проверку естественного завершения выполняет полный прогон.
Скриншоты и `report.json` сохраняются в `QA_DIR` (по умолчанию `/private/tmp/sber-p0-qa`).
Тестовые средства не загружаются приложением и не добавляют ему зависимостей.

Итоговый протокол и контактные листы сохранены в `docs/qa/p0/`. Дополнительные кадры эффектов сняты
в середине анимации и также просмотрены в обоих браузерах.

# Архитектура

Прототип — эталонная реализация движка «Приколов», который переносится в нативные приложения СберKids.
Поэтому слои и интерфейсы здесь такие же, какими будут в Kotlin и Swift (соответствия — в [NATIVE.md](NATIVE.md)).

## Слои

```
┌──────────────────────────── app/ (оболочка = существующие приложения) ────────────────────────────┐
│ экраны (PNG из Figma или HTML-заглушка) · зоны в % · якоря data-anchor · навигация                │
│                         │ bus.emit('task:done', { taskId })                                         │
└─────────────────────────┼──────────────────────────────────────────────────────────────────────────┘
                          ▼
┌──────────────────────────── engine/ (то, что напишем в нативе) ───────────────────────────────────┐
│ triggers (event, shake, tilt, flip, still, multitap, longpress) ◄── sensors (motion/orientation/  │
│        │ fire(payload)                                                       pointer)              │
│        ▼                                                                                            │
│ кандидаты одного тика → rules (зона, экраны, расписание, кулдауны, лимит) → приоритет → effect     │
│        ▼                                                                                            │
│ stage: canvas частиц + DOM-эффекты + UI (тост, чип, альбом), pointer-events: none                  │
│ collection (localStorage) · haptics · sound · лог решений                                          │
└─────────────────────────▲──────────────────────────────────────────────────────────────────────────┘
                          │ JSON по ключу + статика
┌─────────────────────────┴── content/ (CMS-ключ + CDN) ────────────────────────────────────────────┐
│ config.json · effects/*.json (Lottie), картинки · sounds/*.wav                                    │
└────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

| Слой | Знает | Не знает |
|---|---|---|
| Оболочка `app/` | свои экраны, навигацию, когда слать события | что такое прикол, конфиг, эффекты |
| Движок `engine/` | события, сенсоры, правила, якоря по имени, слой эффектов | вёрстку оболочки, селекторы, картинки |
| Контент `content/` | — | — (только данные) |

Единственные точки соприкосновения оболочки и движка: **шина событий** и **якоря** (`data-anchor="<имя>"`,
движок получает прямоугольник через `stage.getAnchorRect(name)`).

## Контракт событий (оболочка → движок)

| Событие | Payload | Кто шлёт |
|---|---|---|
| `screen:open` | `{ screen, zone: 'green' \| 'red' }` | каждый переход; `zone` берётся из `app/screens.js` |
| `task:done` | `{ taskId }` — `dog_walk`, `dishes`, `multiplication`, `clean_room`, `read_book` | отметка дела |
| `tasks:allDone` | `{}` | отмечено последнее дело (сразу после его `task:done`) |
| `moneybox:topup` | `{ moneyboxId, progress, prevProgress }`, 0..1 | открылся экран успеха пополнения |
| `balance:show` | `{ value }` — число, наружу не уходит | открылся главный экран |
| `app:firstOpenToday` | `{ hour }` | первый запуск за день |

Правила контракта: поля можно добавлять, нельзя переименовывать и удалять. `prevX` рядом с `X` —
соглашение для порогов (`where: { progress: { crosses: 0.5 } }`).

## Якоря

| Экран | Якоря |
|---|---|
| все с таббаром | `tabbar` |
| `home` | `avatar` (поднимаемый), `card`, `balance` (поднимаемый) |
| `tasks` | `task-dog_walk`, `task-dishes`, `task-multiplication`, `task-clean_room`, `task-read_book` |
| `tasks_done` | `trophy` |
| `moneybox` | `moneybox-bike`, `moneybox-paints`, `moneybox-headphones` |
| `topup_success` | `success`, `progress` |
| `content` | `feed-1` … `feed-4` (только в заглушке) |

«Поднимаемый» якорь (`lift: true`) на PNG-экране — это кусочек картинки поверх подложки цвета фона:
его можно анимировать (сальто, прыжок), и под ним не остаётся «двойника».

## Жизненный цикл движка

1. Оболочка рисует первый экран, затем (`requestAnimationFrame` + `setTimeout`) лениво импортирует `engine/engine.js`.
2. `boot({ bus, host, configUrl })`: подключает `engine.css`, создаёт `stage`, берёт конфиг —
   override из CMS (`localStorage['prikoly.configOverride']`), иначе `content/config.json?v=<время>`.
3. `validateConfig` нормализует конфиг: битая запись пропускается с предупреждением в консоль,
   битый конфиг целиком → пустой список (движок молчит, оболочка работает).
4. Для каждого включённого прикола создаётся экземпляр триггера. Сенсоры подписываются, только пока
   есть подписчики. Отдельно — `longpress` на `settings.albumAnchor` для альбома.
5. Событие `storage` (CMS в соседней вкладке сохранила/сбросила override) → `reload()`:
   активные эффекты гасятся, триггеры пересобираются, коллекция и кулдауны сохраняются.

## Конвейер решения

```
trigger.fire(payload)
  └─ прикол уже играет и умеет update()?  → update(payload) (непрерывные: голограмма)
  └─ иначе в очередь тика → queueMicrotask(flush)
flush():
  1. дубликаты одного прикола схлопываются
  2. rules.check по порядку: enabled → красная зона → screens → dateRange/timeOfDay
     → кулдаун прикола → глобальный кулдаун → maxPerDay        (первая неудача = причина в логе)
  3. прошедшие сортируются по priority, играет один победитель, остальные — «уступил»
  4. полноэкранный эффект один: новый с бо́льшим priority прерывает текущий, иначе пропуск
  5. effect.play(params, ctx) + страховочный таймер durationMs + 1,5 с
  6. rules.commit, вибрация, звук, коллекция (+ тост, если находка новая), запись «✅» в лог
```

Глобальный кулдаун — пауза после **полноэкранного** эффекта; прикол с бо́льшим приоритетом её не ждёт
(иначе «Все дела выполнены» терялся бы сразу после отметки последнего дела).

`screen:open` с `zone: 'red'` → очередь очищается, все эффекты гасятся немедленно, альбом закрывается.

## Stage (слой эффектов)

- `canvas` на весь телефон (DPR ≤ 2) для частиц, DOM-элементы эффектов (голограмма, Lottie) и слой UI.
- Всё `pointer-events: none` (кроме альбома и чипа разрешения, которые открывает сам пользователь).
- Один общий `requestAnimationFrame` на все эффекты: рендерер возвращает `false`, когда закончил;
  нет рендереров — цикл остановлен, canvas очищен. `document.hidden` → пауза. `dt` ограничен 50 мс.
- `getAnchorRect(name)` → `{ left, top, width, height, right, bottom, cx, cy, radius }` относительно stage.
- `getAnchorElement(name)` — только для `cssAnimate` (в нативе: анимировать view якоря).
- `stats()` → FPS, число частиц, активные рендереры — для debug-панели.

## Интерфейсы модулей

```js
// Триггер: engine/triggers/<type>.js
{ type, sensors: ['motion' | 'orientation' | 'pointer'], validate?(spec) → строка-ошибка | null,
  create(spec, ctx, fire) → dispose }          // ctx: { bus, sensors, stage, settings }

// Эффект: engine/effects/<type>.js
{ type, fullscreen: boolean,
  play(params, ctx) → { stop(), update?(payload) } | null }   // null — играть не на чем (нет якоря)
// ctx: { stage, settings, reducedMotion, asset(src), haptics, sound, payload, end() }
```

Эффект обязан сам вызвать `ctx.end()` и убрать за собой всё; движок подстрахует `stop()` по таймеру.

## Ресурсы и доступность

- Частиц не больше `settings.maxParticles` (150); спрайты эмодзи и фигур кэшируются в offscreen-canvas.
- `prefers-reduced-motion`: частиц ×0,35 без вращения и покачивания, `cssAnimate` → мягкое свечение,
  голограмма без движения и вполовину слабее, Lottie пропускается.
- Ассеты грузятся по требованию (`lottie-web` — только при первом Lottie-эффекте, звуки — при первом проигрывании).
- Звук через Web Audio, `navigator.audioSession.type = 'ambient'` (уважает беззвучный режим iOS);
  глобальный mute — в альбоме и debug-панели. Вибрация молча пропускается там, где её нет (iOS).

## Разрешения (iOS)

`DeviceMotionEvent.requestPermission()` и `DeviceOrientationEvent.requestPermission()` вызываются синхронно
из первого касания (`touchend`/`click`) или по чипу «✨ Включить волшебство». Чип показывается, только если
есть включённый прикол на датчиках, и исчезает после ответа. Нет разрешения — сенсорные приколы молчат,
остальное работает. На Android и в нативе разрешений нет.

## Устойчивость

- Движок не может сломать оболочку: загрузка в `try/catch`, исключения триггеров, эффектов и рендереров ловятся.
- `localStorage` — всегда в `try/catch` (приватный режим).
- Внешних запросов нет: только свой origin, `lottie-web` лежит в `vendor/`.

# screens/

Экраны из Figma (кадр 375 pt, экспорт @2x = 750 px в ширину) в WebP. Имена = id экранов из `app/screens.js`:

`home.webp`, `tasks.webp`, `tasks_done.webp`, `moneybox.webp`, `moneybox_goal.webp`, `topup_success.webp`,
`content.webp`, `transfer.webp` и `tabbar.webp` — закреплённый таббар (375×162 pt, с прозрачным градиентом сверху).

- Новый экспорт: PNG из Figma @2x в любую папку → `node tools/encode_screens.mjs <папка>` (см. `tools/README.md`)
  перекодирует их в `screens/*.webp` того же размера в пикселях (зоны в % не сдвигаются). Непрозрачные — без
  альфы, с прозрачностью (таббар, скруглённые углы `transfer`) — с альфой. Исходные PNG — в истории git (`086163d`).
- Новая картинка → допишите имя файла **с расширением** в `READY_IMAGES` в `app/screens.js` (например
  `'goal.webp'`; PNG и JPEG тоже годятся). Id картинки — имя без расширения. Пока файла там нет, оболочка рисует
  HTML-заглушку и не делает лишних запросов. Регистр в имени важен (GitHub Pages его различает).
- WebP показывают Safari 14+ на iOS 14+ / macOS 11+ и Chrome на Android. Не загрузилась — будет заглушка.
- Нарисованные на экранах статус-бар (44 pt) и home indicator (34 pt) на телефоне срезаются, в рамке на
  десктопе — остаются. Нарисованный таббар (нижние 162 pt, `cropBottom`) срезается всегда — вместо него закреплённый.
- Если таббар на новом экране нарисован с другой активной вкладкой, её подставляют кусочком этого экрана
  (`TABBAR.active` в `app/screens.js`).
- Чужие или устаревшие фрагменты макета закрываются локальными `patches` из `app/screens.js`; такие слои не
  перехватывают касания. `preferStub: true` принудительно использует собственную HTML-композицию вместо растра.
- Калибровка зон: `index.html?debug=1` → «Калибровка» → протяните рамку по элементу → `{ x, y, w, h }` в % от
  картинки окажется в буфере обмена → вставьте точные значения в `zones` экрана в `app/screens.js`.

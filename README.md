# СберKids · Приколы

Хакатон Сбера «Создаём эмоции», трек «Приколы».

**Идея.** В приложении СберKids живёт **Капля** — собственный маленький персонаж. Она сидит в центре таббара и
реагирует на то, что ребёнок делает с телефоном и в приложении: наклон — катится, тряска — кружится голова,
телефон лицом вниз — засыпает, отметил дело — радуется, все дела — танцует. Вокруг неё — короткие приколы:
карта переливается голографической фольгой, осенние листья ложатся на карту и смахиваются пальцем, ночью
экран засыпает и встречает рассвет. Каждый эффект длится секунды, не мешает пользоваться приложением и никогда
не появляется на экранах с деньгами. Найденное собирается в альбом с подсказками-загадками, а реакции Капли,
приколы и сезоны меняются из CMS без релиза.

## Демо

- Приложение: **https://dnnnnnk.github.io/sber-hahaton/** — откройте на телефоне.
- Режим ведущего и разработчика: https://dnnnnnk.github.io/sber-hahaton/?debug=1 — «Сбросить демо», сезон,
  кнопки геройских моментов, имитация датчиков, лог решений движка, подсветка зон.
- CMS: https://dnnnnnk.github.io/sber-hahaton/cms.html — выключите прикол, смените сезон или реакцию Капли,
  нажмите «Сохранить»: приложение в соседней вкладке (и превью справа) поменяется без перезагрузки.
- Сценарий показа на 2–3 минуты с репликами: [docs/DEMO.md](docs/DEMO.md).

На iPhone при первом касании Safari спросит доступ к датчикам движения (или нажмите ✨ в центре таббара).

### Что найти

| Прикол | Как |
|---|---|
| 💧 Капля | живёт в центре таббара на всех зелёных экранах: тап — хихикает, наклон — катится, тряска — кружится голова, дело — радуется, все дела — танцует, долго без касаний — дремлет, свайп — убегает до следующего входа |
| 💳 Голографическая карта | покачать телефон на главном: радужная фольга, бегущий блик и искры заметны уже с ±10° |
| 🍂 Листопад / ❄️ снегопад / 🌸 лепестки / ☀️ солнечные зайчики | тряхнуть телефон (сезон по календарю или из CMS); листья, снежинки и лепестки ложатся на карту, карточки и таббар — их можно смахнуть пальцем; летом по карточкам бегут блики |
| 🙃 Кувырок | положить телефон экраном вниз: ночь, звёзды, Капля спит; поднять — рассвет и «Доброе утро!» |
| 💤 Тихий час | телефон лежит 6 секунд: 💤 над аватаром, Капля дремлет |
| 🐾 Лапки, 🫧 пузыри, 🔢 дождь из цифр, ✨ искорки, 📖 летящие буквы | отметить дело на вкладке «Дела» — у каждого дела свой эффект, отклик на каждый тап сразу |
| 🎉 Праздник дел | отметить все дела |
| 🪙 Звенящие копилки | тряхнуть телефон в «Копилках»: монетки звенят в кармашках видимых копилок, их число зависит от прогресса |
| ⭐ Звезда копилки | пополнить копилку (Lottie) |
| 🤸 Сальто | три быстрых тапа по аватару |
| 📒 Альбом находок | долгое нажатие на аватар; подсказки к ненайденному — загадки |

В конфиге есть и выключенные заготовки: «Красивое число» на балансе 777/1111 и «Вехи копилки» (25/50/75/100 %).
Включаются в CMS одной галочкой.

## Как устроено

```
app/      оболочка = существующие приложения: экраны из Figma, зоны, якоря → события в шину
engine/   движок = то, что пишем в нативе: триггеры → правила → эффект на прозрачном слое
content/  CMS-ключ + CDN: config.json, Lottie, звуки
```

- Новый прикол — это запись в `content/config.json` (+ ассет). Новый тип триггера или эффекта — модуль
  в `engine/triggers` или `engine/effects` и строка в реестре.
- Капля — тоже запись конфига: триггер `presence` (каждый зелёный экран), эффект `resident` и таблица
  `reactions` «событие → реакция», которую контент-менеджер правит в CMS выпадающими списками.
- Правила: красная зона (перевод, оплата, пополнение…) — эффект гаснет мгновенно; экраны, сезон и время,
  кулдауны, лимит в день, приоритеты. Каждое решение видно в `?debug=1`.
- Слой эффектов не перехватывает касания (единственное исключение — круг тела Капли, чтобы тап по ней не нажимал
  вкладку под ней); один `requestAnimationFrame`, который стоит, когда ничего не движется; лимит частиц, DPR ≤ 2,
  пауза в фоне, `prefers-reduced-motion`. Движок грузится после первой отрисовки, ассеты — по требованию.
- Детская карта на главном — собственная зелёная HTML-композиция с живым балансом (вместо растра с котом).
- Сторонние образы из черновых макетов закрыты нейтральными локальными слоями оболочки; вкладка «Контент»
  собрана собственной HTML-композицией без внешних картинок.
- Ни одного внешнего запроса, никаких данных наружу, никаких лотерей и стриков. Ассеты приколов ~0,2 МБ.

## Перенос в натив

Оверлей поверх приложения (Compose `Box` / SwiftUI `.overlay` с `allowsHitTesting(false)`), Lottie уже есть
в обоих приложениях, сенсоры — `SensorManager` / `CoreMotion`, конфиг — по существующему CMS-ключу.
Оценка — около 16–19 дней на платформу с P2, таблица соответствий в [docs/NATIVE.md](docs/NATIVE.md).

## Запуск локально

```bash
python3 -m http.server 8000
```

Затем http://localhost:8000/ , http://localhost:8000/?debug=1 и http://localhost:8000/cms.html.
Сборки нет — чистые HTML/CSS/JS-модули; единственная библиотека `lottie-web` лежит в `vendor/`.

## Показ

Сценарий на 2–3 минуты с репликами ведущего и запасными кнопками на случай капризного датчика —
[docs/DEMO.md](docs/DEMO.md). Перед показом: `?debug=1` → 🛠 → «Сбросить демо».

## Проверки

При запущенном локальном сервере и установленном **инструменте разработки** Playwright. Для тестов надёжнее
`node tools/serve.mjs 8000` (без зависимостей): `python3 -m http.server` под параллельной загрузкой модулей
иногда сбрасывает соединения.

```bash
node tests/p0.assets.mjs
node tests/sound.lifecycle.mjs
node tests/p0.audit.mjs
node tests/p2.smoke.mjs
node tests/demo.smoke.mjs
node tests/perf.mjs
```

`demo.smoke` — регрессии демо-сценария: быстрые отметки дел, откат на следующий прикол, данные экранов,
Капля и её реакции (включая смену реакции из CMS), голограмма, кувырок, смахивание погоды, тихий час,
загадки и режим ведущего — в Chromium и WebKit. `perf` — геройские моменты при CPU ×4 (цель ≥ 55 FPS).

P0 проверяет все 8 экранов и зоны касания, все 15 включённых приколов и 22 визуальных варианта,
CMS/JSON/экспорт/горячее обновление, альбом и debug в обоих браузерах при 375×812.
Проверки ассетов и отмены звука запускаются обычным Node.js. Результаты и границы приёмки —
[docs/P0_QA.md](docs/P0_QA.md).

Приложению Playwright не нужен. Можно использовать уже установленный пакет через `PLAYWRIGHT_MODULE`
(абсолютный путь), сервер в подпапке через `APP_URL`, папку скриншотов через `QA_DIR`.
Прогон проверяет Chromium и WebKit при 375×812, CMS при 1280×900, жесты и уход с экрана, реальные клики
сквозь эффекты, красную зону, горячее выключение из CMS, общий лимит частиц, reduced motion, mute,
освобождение рендереров, отсутствие ошибок и внешних запросов. В Chromium измеряется отзывчивость при CPU ×4.
Чувствительность датчиков, звук, вибрацию и FPS на телефонах проверяют отдельно: [docs/DEVICE_QA.md](docs/DEVICE_QA.md).
